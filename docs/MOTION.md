# Homepage motion

How the site moves, as built. Code comments point here by section name. The choreography is pure functions of scroll in `src/lib/motion/home.ts` (and `footer.ts`), unit tested in `tests/motion.test.ts`; the components that drive them are `HomeMotion.tsx` (homepage), `MotionRoot.tsx` (every page), `Preloader.tsx`, `ScreenTransition.tsx` and `MainNav.tsx`.

The Studio Foundry motion specification Sebra supplied (MOTION-SPEC.md, 22 October 2026) was the early reference for the engine and the section order. The site has since moved away from it in most details (see "Where this differs from the spec"); this file describes the site, not the spec.

## Motion vocabulary

One set of rules for the whole site (`home.ts` header; the CSS side is in `globals.css`, `:root`):

- **Sheets.** A section hands over by a sheet rising from the bottom edge over a layer that recedes: it grows 8% at most, darkens, or dims to 0.72. Timed sheets use `--e-sheet` over 0.6 to 1.0s; scrubbed wipes take about 0.3 screens.
- **Masks.** Display type never fades. Each line rises from its own mask (`MASK`, 120%) and leaves upward through it (`roll()`). Masked lines take 0.9 to 1.2s timed, or 0.24 to 0.34 screens scrubbed, 0.03 to 0.06 screens apart. Only small labels, captions and blocks may fade.
- **Eases.** Entrances `power3Out`, exits `power2In`, no overshoot. Hover and tone changes take 0.3s on `--e-ui`.
- **Rhythm.** Each beat holds 0.6 to 0.8 screens fully composed and hands over in about 0.3. The next section's first element starts entering before the last one leaves, so no frame is empty for more than 0.15 screens.
- **Materials.** The ivory sheet over the hero, stone under Works, ivory for Values, dusk into the night Services (an OKLab blend), the ivory Contact sheet and the charcoal footer.

## Scroll engine

- **Lenis 1.3.27** (`src/lib/motion/engine.ts`): duration 1.2 on an exponential ease-out, vertical wheel smoothing, native touch scrolling. With reduced motion: duration 0, linear, no wheel smoothing.
- **One frame loop** runs everything in a fixed order: Lenis, frame callbacks (roll links), then the modules by `ORDER`: ground, hero, intro, works, values, the Services picture, the Services copy, the Services to Contact handover, contact, the footer, parallax, and the header last. `dt` is clamped to 50ms, so a tab left in the background does not jump when it comes back.
- **Progress values.** `sso` (0 when an element's top meets the bottom of the screen, 1 at the top) and `hso` (−1 when its bottom meets the bottom of the screen, 0 at the top). Ranges come from the `offsetTop` chain, so transforms never feed back into them, and are re-measured on resize, font load, body resize and route change. The screen unit is `100lvh`, so a phone's toolbar does not change the timeline.
- **Writes.** `setStyle` writes only when a value changes, and the modules write transforms, opacity and clip-path, so a frame never invalidates more than the elements that move. The one custom property written per frame (`--ground`, on the phone header bar) is registered as not inherited.
- **Keeping the place.** After a resize or rotation the engine puts the reader back at the same point of the same section.
- **Tracks.** The pinned, scrubbed layouts run only when motion is allowed, JavaScript runs and the screen is at least 500px tall (`TRACKS_QUERY`, the `tracks:` Tailwind variant). Otherwise every section shows a still, ordinary layout with all content visible (see "Reduced motion and still layouts").

## Load sequence

| Time | What happens |
|---|---|
| Before first paint | The head script (`motionScript`) sets `data-motion` for visitors who allow motion, and sets every flag after 8s whatever happens, so the page can never be held. A graphite screen is in place. |
| 0 to about 1.35s | The outline of Ontario draws itself in CSS (the mainland over 0.9s, the islands overlapping its end). The GTA dot pops at 0.95s and rings out once. |
| At least 1.25s from navigation | The screen waits for the strokes, the fonts and the opening picture (capped at 3.5s). |
| T₀ | The page is put back at the top, and the document gets `data-loaded` and `data-revealed`. The drawing grows 2.4 times around the dot and fades (0.7s, accelerating). From 0.25s an iris opens from the dot itself (1s, `--e-sheet`, a registered `--hole` radius in the screen's mask). |
| T₀ + 0.45s | The hero picture has been settling from 112% around the same point (1.8s). The name rises out of its mask (1.2s). |
| T₀ + 0.85s | The statement's two lines rise, 0.09s apart; the caption fades in at 1.15s. |
| T₀ + 0.9s | The header's row comes in item by item (from 0.3s on other pages). |
| End of the iris | `data-preloaded` is set and the screen is removed. Scrolling is released at 70% of the iris (or 8s after navigation). |

Browsers without registered custom properties get a 0.6s fade instead of the iris. After a page transition the hero entrance runs sooner, as the cover lifts (`data-arrival="route"`, which hard loads never have). The hero's CSS entrance moves each line's inner span and the scroll moves the span around it, so neither overrides the other.

## Sections (scroll map at 1440×900)

Positions are in screens. The page scrolls 19.6 screens at 1440×900 and 21.1 at 390×844.

| Section | Track | Behaviour |
|---|---|---|
| Hero (`Hero.tsx`) | 0 to 2.5 (250vh, pinned 1.5 screens) | From half a screen the intro's ivory sheet rises over it. The statement leaves upward through its masks first (0.02 to 0.37), then the name (gone by 0.72, lifting 0.08 screen), before the sheet reaches them. The caption fades by 0.3. The picture recedes under the sheet the whole time: it drifts up, grows 8% and darkens (`heroState`). |
| Intro (`Intro.tsx`) | 1.5 to 6.6 (510vh for two paragraphs, `introPhases`) | An ivory sheet whose top sits a screen up, inside the hero's track. Six studies travel one squircle path (`orbitPath`), spaced by arc length so they never crowd, at 0.075 turns per screen. Each glides in from 1.8 times the ring as its part of the sheet comes up, settling from 118%, and breathes 3%. The two paragraphs rise line by line through the middle (`introLine`), 1.75 screens apart. At the end the ring is flung out to 1.9 times its radius over one screen, and the stage releases 0.4 screen into the fling. On portrait screens a study shows only once it is clear of the copy (`introCopy`, a ring tilting behind the text), and a study flung down dissolves before it reaches the stage's lower edge (`ORBIT_EDGE_FADE`). |
| Works (`Works.tsx`) | 6.6 to 10.8 (420vh: three 140vh panels under one pinned stage) | One notched frame holds the three studies. The first picture rises from the bottom of the screen while the stage is still coming up under the intro's fling. At each handover (0.3 screens) the next picture wipes up from the bottom over the last, which dims to 0.72. The outgoing lines (eyebrow, title lines, button) leave upward just before the wipe and the incoming ones rise from about its midpoint, so two lines never print over each other. The button travels 1.3 times as far, so its focus ring clears the mask; its plate fades with how much of it shows (`worksButton`), and it takes the pointer only while in place. Keyboard focus on a button scrolls to its study. On short landscape screens the text keeps below the corner label (`--works-label-b`). The ground turns to stone under the section. |
| Values (`Values.tsx`) | 10.8 to 14.8 (400vh: four 100vh blocks under one pinned stage) | Each picture grows from 0.72 to full size as it reaches the centre. The words are stacked in one cell and roll like an odometer: the outgoing word leads by 0.02 screens and both travel on one ease over 0.16 screens, so they never print over each other, and each word holds 0.58 screens or more. Every word and description is set twice: ink over the ground, and ivory inside a mask clipped to the union of the pictures on screen, so a picture's edge splits a word into two colours. A description line shows in one copy only (ivory while its letters are all over a picture, ink otherwise), so a passing edge never cuts a line. Below 1024px each word is fitted a little wider than its picture, and on any screen a word that would come too close to the corner label shrinks until it clears it (`valuesWordSize`). The pictures dim to half brightness as dusk falls. |
| Dusk | Services sso 0.24 to 0.46 | The ground turns from cream to night quickly, blended in OKLab so the middle stays warm. The last Values word has left by sso 0.36; the two sections' pictures fill the screen between the last word and the Services heading. |
| Services (`Services.tsx`) | 14.8 to 18.0 (300vh track, pinned two screens) | See below. |
| Contact (`Contact.tsx`) | 18.0 to 19.5 | An ivory sheet that rises over Services. See below. |
| Footer (`SiteFooter.tsx`) | 19.5 to the end | See "The footer". |

Every scrubbed value is a pure function of scroll position, so scrolling back up reverses everything exactly. The Services picture swaps are timed rather than scrubbed, and run back the same way.

Each pinned section's label (its heading and note) rolls in through its mask as the stage comes up: Works from sso 0.3, Values from 0.62.

### Services

- **Pinned everywhere it fits.** Wide screens 720px or taller and phones 620px or taller get the 300vh track with the whole composition pinned for two screens. The stage's sizes are capped by the screen's height, so the eyebrow to the "All services" link fits in about 700px at 720 tall. On portrait tablets the picture is never taller than its 4:5 at the column's width. Phones stack the picture above the heading and list, its top always clear of the 80px header bar; between 620 and 720px tall they tighten (smaller gaps and heading, a picture of at least 4rem; the rows keep their 44px).
- **Entrance.** The stage rides 0.3 screen ahead of its track until sso 0.4, so the picture follows close under the last Values picture, then settles into the pin on `power2In`, its speed reaching 0 as it pins (`servicesLead`). The picture's sheet wipes up from the bottom of the screen as the frame comes into view and the picture settles from 120% (`servicesReveal`, `riseInset`). Once the ground is past half night the eyebrow (sso 0.34), the heading's lines (from 0.36, 0.06 apart) and the rows (from 0.44, 0.04 apart) rise out of their masks, each row's rule drawing across. Each row's number and tag (and, after the last row, "All services") are switched on once the label is most of the way up (`servicesRow`, `data-services-in`) and fade in on their own over 0.3s, a CSS transition rather than a value written every frame. The seventh row is in place at sso 0.98, so the composition is whole for the whole hold. Only transforms, opacity and clip-path are written.
- **Hold.** Scrolling walks the rows: the hold is shared evenly between them (`servicesIndex`). The frame shows the row hovered (with a fine pointer), else the one focused, else the one reached by scrolling; a new scroll position takes over from a resting pointer. A hover is taken only from the pointer moving, and on the pinned track only while the stage holds (`servicesHold`), so rows rising or scrolling under a resting pointer never pick a picture. While the page is held (a page transition, the menu, the preloader) the frame keeps its picture: a click on a row moves focus and the transition's cover passes under the pointer, and neither swaps away the picture just chosen. Each new picture wipes up over the last (0.7s), which darkens under it. The pictures are stacked layers (`swapTo`, `swapSettle`): a quick run over the rows never cuts from one picture to another, and going back to a picture still in the stack slides the sheets above it back down. The active row's number carries a small red dot; the other labels dim to half only while one row is singled out.
- **Keyboard.** Tabbing into the list from outside while the stage is not pinned scrolls to that row's place in the hold, where the list is whole. Focus inside the stage never moves the page, and moving on to "All services" keeps the last row's picture.
- **Wide screens too short to pin** (under 720px tall): the section flows, starting close under Values. The heading rises with the track as above, each row arrives from its own place, and the picture follows the row crossing the middle of the screen.

### Services to Contact

Contact's ivory sheet rises over Services, which lags behind the scroll by up to 0.35 screen and dims to 0.45 as it is covered (`servicesHandover`). The Services stage has released about 0.2 screen before (at 1440×900), so this never moves a pinned stage. The header turns back to ink as the sheet reaches it.

- **CONTACT** is cut in letter by letter, each rising from its own mask, 0.03 screens apart (`contactLetter`). Screen readers get the word once. Each letter is a box of its own, which loses the face's kerning between them, so the pairs that kern (O–N, T–A, A–C) get it back as em margins in the stylesheet, measured against the plain word, which also holds without JavaScript; the contact module re-measures and refines them.
- **Cards** rise 48px, one column a step behind the other on wide screens, their pictures wiping up from the bottom and settling from 112% (`contactCard`). From 768px wide the two cards share their rows (picture, text, foot) through subgrid, so "Get in touch" sits on the same rule as the rating and credentials.

### The footer

On every page the footer's content rises out from under the sheet above it, lagging by up to 0.3 of its height (or of a screen) and in place once it is all on screen or the page ends (`footerProgress`, `footerLift`). The Ontario outline draws itself stroke by stroke as it comes into view, the GTA dot landing last (`footerDraw`, `footerStroke`, `footerDot`): a bookend to the preloader. The footer's own call to action stands down on pages that already close on one (the homepage's Contact, an inner page's `CtaPanel`, the contact form). The 404 draws its own outline beside its numeral, so the footer's stands down there.

## Navigation and page transitions

- **Header** (`MainNav.tsx`): past 80px of scroll on screens 768px and wider, the top row leaves right to left (Contact first, 30ms apart, 0.28s, `--o`) and only then does the menu button rise into the corner (0.5s from 0.26s, once Contact's fade is all but done); coming back above 80px the button drops first (0.2s) and the items return left to right. Phones keep the logo and the menu button. The header reads the ground 64px down: ivory type over the hero, the night ground, dark sections and the footer, ink elsewhere. A dark section counts only until the next one begins, so a sheet sliding over it turns the header at once. Every tone change takes 0.3s: the bar, the type, the menu button and the logo, whose two versions share one grid cell and cross-fade. The menu button carries a 1px ring of its own colour, so it never merges with the ground. On phones the collapsed bar over the homepage hero is only a dark gradient that fades to nothing (no slab across the picture), on a layer of its own that fades in as the bar's ivory fades out, so the crossing never shows a grey band; light bars carry a hairline under them. On the homepage the phone header bar takes the ground's colour (`headerGround`), ivory as soon as Contact's sheet reaches it. Without JavaScript the header sits at the top of the page in the tone of the ground it starts on, and scrolls away with it.
- **Menu**: unfolds from the button's own outline (0.42s, `power2InOut`, opaque until near the end), the links rising one after another (0.5s from 0.15s, 30ms apart). Closing plays the same animations backwards from wherever they are (links three times as fast, the panel 1.35 times), so a quick second press reverses rather than snapping. On phones it fills the screen with the call to action at its foot (a short phone drops the line about the studio to keep it on screen); wider, it is a panel in the corner over a light scrim. The content scrolls inside the panel when it must, fading out under the logo and the close button, and at its foot too while there is more below (`data-more`), so the last line showing reads as more to come rather than cut off. Escape, a click outside (on the scrim) and navigation close it. Focus is trapped while it is open and returned to the button; each link's rising mask lets 4px past its edge, where the link's focus ring sits (1px out, clear of the numeral), so the mask never clips it.
- **Roll links**: header, menu and footer links roll their characters (0.4s, 0.02s apart) on hover and keyboard focus, and roll back from wherever they have got to.
- **Link buttons** (`LinkButton.tsx`, `wipe.ts`): on hover and keyboard focus a darker sheet of the plate's own colour wipes across the label (0.45s, `--e-sheet`; charcoal on ink, stone on ivory) and leaves forwards, through the far edge. The fill is one band (`--lb-a` to `--lb-b`) that both the wipe and the outline tones' second label are clipped to, and each change runs the band on from wherever it is (in a time in proportion to the way it has to go), so a pointer passing quickly over a button leaves a sliver that runs out ahead of it, and a pointer coming back while the fill leaves turns it round: nothing ever jumps. Without JavaScript the fill simply runs back the way it came; a highlight passes over the label (0.6s); just after (0.06s), the icon cell turns a quarter on its cube (0.45s, `--e-out-strong`) to a face whose arrow is the button's one red; both cells round their corners by 2px. The outline tone (on paper) and the ghost tone (on dark grounds) are a 1px ring that fills with ink or ivory, the label changing colour exactly where the fill has reached. The contact form's submit and the map card use the same face (`LinkButtonFace`); the form's shows a spinner while sending. In print a link button is an ink outline with an ink label. FAQ toggles, related-link rows and the footer's call to action use the square cell on its own, the cube turning as their row is hovered or focused (the footer's is the one red square, 3.5rem). Focus rings sit 4px out, brand-300 on dark grounds.
- **Page transitions** (`ScreenTransition.tsx`): on a click to another page the link dims at once and a dim underlay fades in (0.25s); a graphite sheet rises from the bottom edge to cover the screen (0.6s, `--e-sheet`) while the Ontario outline draws on it stroke by stroke (from 0.15s, 0.05s apart, the mainland 0.55s) and the GTA dot pops as the last stroke closes. Only then does the router change the page, so its commit never stalls a line. Once the new page is laid out and its opening picture decoded (at most 0.9s), focus moves to its main content and the sheet leaves through the top (0.6s, `power2InOut`, which gets going sooner than `--e-sheet`), the dimming clearing with it (0.3s); the outline stays on the sheet, drifting up 16px, until the sheet's edge clears it, so the exit never opens on a plain graphite screen. The pressed link lets go as the cover lifts, however the navigation ended; the page's entrance runs on the route timing (`data-arrival="route"`). Each navigation has an id, so a late timer from an earlier click can never lift the cover over the wrong page, and a click while the cover is lifting turns it back. With reduced motion it is a 0.3s crossfade.
- **History and in-page links**: every page's scroll position is kept by URL (path, query and fragment, for the session). Back and forward cover the screen with a quick fade (0.28s), hold the router until it is covered, return the page to the pixel the reader left and lift the cover (0.32s); entrances and reveals do not replay on the way back (`data-returning`). A link to the page already showing glides to its top and closes the menu; a link that only changes the query (the contact form's preselected service) does the same and lets the router swap the page in place, keeping the form's choice, and the position it left is kept under its own URL for Back. From the keyboard, either moves focus to the page's main content, as a navigation does (wide screens put the menu button away at the top). In-page links ("On this page", the skip link) glide to their section (1.1s, the wheel's exponential ease; a jump with reduced motion), add a history step, and then move focus to the section; their heading lands level with the sticky index. Any glide waits for the menu to release the page first. Nothing the reader has passed is left blank: a sweep every tenth frame, when the page has moved since the last one, shows any block already above the screen, and stops once nothing is left hidden.
- **Inner pages** (`InteractionEffects.tsx`, `reveal.ts`): the page header enters in order once the preloader or transition clears; below it headings rise line by line, and rows, rules and blocks follow one another in reading order (60ms apart, at most 480ms) as they reach the bottom 8% of the screen. Anything that takes focus or the pointer shows at once.
- **Parallax** (`MotionRoot.tsx`): pictures marked `data-parallax` sit at 120% and drift through a tenth of their height as they cross the screen.

## Reduced motion and still layouts

With `prefers-reduced-motion: reduce`: Lenis duration 0 and no wheel smoothing; no preloader; every homepage section shows its still layout with all content visible; the Services picture follows a hover or focus at once; the Contact letters, cards and footer outline are simply there; roll links, parallax and the inner-page reveals are off; page transitions and Back and forward are a 0.3s crossfade, and glides are jumps; CSS durations collapse to 0.01ms.

Screens under 500px tall (a phone on its side) and visitors without JavaScript get the same still layouts, with motion otherwise allowed. So does a printed page, from wherever it was scrolled to: the tracks CSS applies to screens only, and the engine turns the tracks off from `beforeprint` to `afterprint`, so every module clears what it wrote before the page prints and writes it again after. In print a study or a value stays on one sheet with its picture, dark grounds keep their graphite, and sticky boxes print in the flow. Every split line or letter keeps its text for screen readers once.

## Where this differs from the spec

- **Choreography.** The spec's section behaviours were replaced section by section: the hero is covered by the intro's sheet rather than fading, the orbit is one squircle path rather than seven orbit slots, Works is one pinned viewer with wipes rather than resolving panels, Values is an odometer with a union mask, Services pins on every size, and Contact is a sheet with letters cut in. Display type never fades.
- **No WebGL layer.** Its shaders were never captured, so nothing of them is guessed. The `homeCard` FLIP between a works card and its page belongs to that layer and is not built either.
- **Colours** are PermitGuys' ivory (`#f4f1eb`), stone and graphite (`#191918`), and the ground goes through dusk into night for Services.
- **The preloader** draws Ontario's outline and opens with an iris from the GTA dot rather than the arch logo; the transition panel and the footer carry the same outline.
- **Link button corners** round by 2px with a CSS `clip-path` rather than the reference's hand-built path morph, and the buttons stay square-cornered at rest, in the brand's ink, ivory and stone; red is only the turned arrow and the footer's one square.
- **Short screens** get the still layout rather than the reference's short-landscape variant.

## What could not be verified

- **Real devices.** Checked in headless Chromium at 1440×900, 1280×720, 1280×680, 1024×720, 820×1180, 390×844, 375×700, 360×740, 360×620, 320 wide and 844×390, with frame captures, wheel recordings forward and back, and traces at four times CPU throttle; not on a physical phone or in Safari or Firefox (the iris needs registered custom properties; others get the fade).
- **Frame cost.** Through the dusk at four times CPU throttle the median frame takes about 30ms of main thread and the slowest about 57ms; unthrottled, frames there stay near 9 to 10ms. Per frame the time is mostly the scroll update, the style recalculation of the elements being moved, and paint (the clip-path wipes repaint their pictures, and layers at the edge of the area Chrome keeps painted repaint as the page scrolls). The root's night ground is no longer read by any style rule, so turning it on and off (as the dusk falls, and as Contact reaches the header) no longer restyles the whole document, which had cost a 20ms frame each time. The footer's outline is on its own layer, so drawing it repaints only the outline. In this environment's software rendering the last screen before the footer still shows a few 16 to 27ms frames while the compositor rasterises; not measured on real hardware or a low-end phone.
- **Line counts** depend on the fonts actually loaded; line splitting re-runs whenever a block's width changes.
- **The reference.** Only a still frame of Sebra's video arrived and the live reference site cannot be opened from the build environment.
